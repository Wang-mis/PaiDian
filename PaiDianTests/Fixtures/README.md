# 音频定位固定样本

`seek-marker.flac` 是项目自生成的 130 秒、44.1 kHz、单声道、16 bit FLAC，不包含歌曲、录音或第三方内容。信号由时间编码的扫频和确定性噪声构成，每 8 秒改变有效位数和熵；压缩后码率变化，避免固定码率样本掩盖近似定位错误。文件包含合法的帧定位表。

需要重新生成时，在独立 Python 环境安装 `numpy` 与 `soundfile`，执行 `python scripts/generate_seek_fixture.py`。脚本使用 FLAC 编码级别 0，将音频帧保持在约 26 ms，并验证最终文件与原始 PCM 逐样本一致。日常构建和测试只读取已提交的 FLAC，不需要 Python 音频依赖。

`PreciseSeekDeviceTests` 使用实际播放路径的资源创建方式，对照完整顺播 PCM 验证跳转后的内容位置；在音频混合器预滚结束后采集 350–1000 ms 内的音频块，要求波形匹配且位置误差不超过 100 ms。测试附件仅记录数值；自生成样本匹配失败时可附加诊断块，真实歌曲测试不附加音频。

`seek-marker.m4a` 使用同一份自生成 PCM，由 macOS 自带 `afconvert` 编码为 AAC，并将 MP4 样本索引移至文件前部、同步修正 chunk offset。它用于受控 HTTP 的未缓冲跳转测试：允许初始 256 KiB 通过以完成起播，随后冻结网络、确认目标尚未缓冲，再恢复传输。索引不完整的 MP3 在精确时间模式下可能先扫描整文件，不能用这种文件证明未缓冲跳转。
